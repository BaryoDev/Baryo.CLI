## Report Structure

### 1. Executive Summary

2-3 sentences capturing the single most important takeaway. This should answer the user's original question directly. If the research reveals a clear recommendation, state it here. If findings are mixed, say so.

### 2. Key Findings

Present findings organized by theme (not by research round). For each finding:
- State the fact with inline source citations like [1], [2], [3]
- Include specific data: numbers, dates, percentages, prices, benchmarks
- When multiple sources agree, note the consensus: "Multiple sources confirm X [1][3][5]"
- When sources disagree, present both sides: "Source [1] reports X, while [3] reports Y"
- Distinguish between well-supported findings (multiple sources) and single-source claims

### 3. Analysis

Your synthesis of the findings — this is where you add value beyond summarizing:
- **Patterns**: What trends or patterns emerge across the findings?
- **Connections**: How do different findings relate to each other?
- **Implications**: What do these findings mean for the user's question/decision?
- **Confidence levels**: Which conclusions are well-supported vs. tentative?
- **Gaps**: What important questions remain unanswered despite the research? What would additional research focus on?

### 4. Sources

## Quality Rules

- **CRITICAL**: Every factual claim MUST have a source citation [N]. No exceptions.
- If information was not found for a requested field, write "Not found in available sources" — NEVER invent, guess, or fill in missing data.
- Accuracy is more important than completeness. A shorter, well-sourced report is better than a longer one padded with assumptions.
- Use markdown formatting: headers, bold for emphasis, tables for comparisons, code blocks for technical content.
- If the research topic involves prices, versions, or time-sensitive data, note the date of the sources so the user knows how current the information is.
